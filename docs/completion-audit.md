# Scaffold Web Launch Completion Audit

Last audited: May 14, 2026.

## Objective

Resolve the launch-readiness audit blockers for Scaffold Web: repair `check:prod` drift, refresh launch evidence docs, make smoke/release verification repeatable, address Rohlax DNS readiness, rerun the relevant gates, and preserve existing user/workspace changes.

## Success Criteria

1. `pnpm check:prod` reflects actual launch state, fails on real blockers, and no longer drifts from the docs, release scripts, or current tests.
2. Launch evidence docs identify current blockers, owners, required actions, verification commands, waiver rules, and latest gate evidence.
3. Smoke and release gates are repeatable against the built app with signed-out access checks gated by `REB_DEV_UNGATED_ACCESS=0`.
4. Rohlax DNS readiness is checked directly, documented with exact Cloudflare/Vercel actions, and remains blocking until `www` and `admin` hostnames resolve.
5. Relevant local gates have been rerun after changes.
6. Existing user/workspace changes are preserved and not reverted.
7. Any remaining production blockers are documented as external dependencies, not hidden by passing local tests.
