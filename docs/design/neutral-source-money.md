# Neutral source money controls — prepared implementation contract

The accepted scope is ADR0010 and ADR0012. The implementation in this isolated source packet is prepared; native schema, real Auth and rendered browser qualification are pending. Commercial terms and provider authority remain external gates.

A qualified published internal-app or bundle source determines its creator and canonical definition identity `system-source:<source System UUID>`. A business or agency creator uses the same money listing port and qualification checks. Private source sharing and exact owner installation authority remain with the existing Version producers. Listing does not expose a source definition or customer records.

`SourceListing` composes the existing Card, Button and SelectInput. It chooses an actual qualified source revision and an existing written creator agreement. The source, creator and definition are derived by SQL. An unknown response preserves the exact source/agreement request; matching readback is checked before graph adoption. Historical listing existence records no invented historical requester.

`SourceMoneyConfiguration` is rendered only in the authenticated operator page. It records explicit source prices or creator agreements already decided in writing. The operator supplies the actual source revision and complete values/references/effective dates; SQL derives the beneficiary and definition. Customer and agency creators have the same eligibility. Agency referral agreement eligibility continues independently through the existing producer. Uncertain commands freeze form editing and can only retry the identical command; exact actor/command/source acknowledgment is required.

`VersionTerms` is scoped to the server-authenticated actor and business. It shows real installed qualified Versions, their current release and matching written prices. A current business owner accepts a precise period and reviewed release. SQL holds current actor/owner/business/payer billing home, Version/system, source qualification, listing/maintenance and written approvals, then freezes source/listing/creator/release/payer/price/period lineage. A release mismatch refuses admission. Business or agency payment uses that party's billing home; terms grant no payment mandate or agency authorization to charge.

Direct acknowledgment and unknown-response recovery bind the exact owner actor, Version/release, original installed source, creator/listing, price/currency/amount and UTC microseconds. A mismatching receipt is rejected before adopting any graph; the original graph and request remain visible. Controls abort owned requests on actor/workspace changes or unmount, retain drafts during errors and move focus only when focus has stayed at the originating control or document body. Current read-only, unconfigured and future-work-closed states retain history without offering new owner acceptance.

The verified provider event path records a settlement using the frozen payer/customer and delegates legacy collections to the original writer. New generic creator accrual follows original platform/agency accrual, preserves wholesale agency-share suppression and recorded attribution, and reconciles retained loss receipts. Accepted observation has no current actor/payer/source reauthorization. It dispatches no provider effect. Existing payout authority/profile/current recipient and recovery contracts remain unchanged.

`creator_version_paid_periods` holds financial metadata, never source definitions, records, grants, accounts or credentials. Restricted foreign keys retain the actual Version release and original identities. Historical updates/deletes are refused. Tenant deprovision does not own this business financial table; workspace exit retains it. The inverse removes only exact new ports and retains all populated history. Reapply validates retained shape/owner/table and column ACL/RLS/policies/constraints/FKs/index/immutable trigger under a write-blocking lock. Schema3 exports include scoped retained lineage through the existing pure export authority and existing owner delivery/download gates.

Release proof still requires the composed exact migration inventory, actual native compile/catalog/read-only/race/drift refusal and populated inverse/reapply history, generated types/exposure, real owner/creator/operator HTTP journeys and browser states. The current ordinary private source authoring HTTP path is agency-only; a separate customer/business creator source-authoring producer remains a neutral-model gate. PaymentIntent dispatch/mandate, governed refunds and provider/commercial qualification remain separate full-release work.
