## What changed

Ask turn resolution previously used only work-derived System IDs. A stored
installed Version can have a distinct canonical System ID; its Ask request then
returned404 before the model/tool ran. The actual route now supplies the existing
merged stored-plus-existing System catalog, and resolution filters its business
scope. Each native tool call separately rereads the merged graph and binds the
selected canonical System to the native saved work and optional lineage/runtime.
Source System, Version System, Version lineage, native work and command identity
stay distinct. No UUID equivalence or legacy client-record authority is invented.

`read_system view:native_application` exposes the supported app definition,
current native design/Version revisions and recent release metadata. It omits
record values, maintenance identity and credentials; it explicitly does not
claim complete archived history. The existing native app read and Version
access/runtime services remain authority. Missing, foreign, retired or unsupported
native work cannot be substituted with a source snapshot or arbitrary runtime.

The nineteenth ordinary tool, `draft_system_change`, supports one app title or
existing field-label change. The current turn must first successfully read that
exact app identity. Every tool rereads direct actor/exit authority; the native
services recheck their own current authority. A non-Version app uses the existing
native maker/candidate-editor gate, revision-pinned revise and real isolated
rehearsal, then current exact Needs you source/revision identity. A Version uses
its existing management and source-standard/compare authority, one override and
the existing prepared-release decision. Arrays are atomic Version values; the
whole current field array changes only the requested label. No unsupported dotted
array-index override is fabricated. The current exact decision determines the
route, including Strelva review when policy requires it. There is no publish,
release, rollback or send port in the new adapter.

Live releases, accepted/submitted records, field IDs/types, components, accounts,
maintenance and source definitions remain unchanged by these presentation drafts.
A partial preparation reports a saved/uncertain draft rather than readiness, and
requires a successful current read before another tool write. A missing exact
decision cannot be called prepared. An unsupported native runtime or absent maker
capability becomes a Request at Asked using the person's original words; it grants
no new maker/owner capability. Larger adaptation, new app creation and arbitrary
runtime building remain unsupported by this bounded tool. This is genuine
supported native preparation, not completion of all native assistance or P07.

SourcePackageControls now keys its scope by workspace and source System, keeps a
synchronous immutable pending input, validates exact successful source/revision
receipts, aborts/ignores unmounted and superseded work, and holds writes after an
uncertain response. Read current package uses a no-store GET and never resends a
mutable listing or an opposite review. Exact observed state can resolve uncertainty;
an acknowledged command or structured4xx refusal requires a current same-source
read. A contradictory/foreign/malformed current read stays held. Old scope state
disappears on switching. This pending state is component-local; it does not create
durable command identity across navigation or claim that an observed final state
proves which actor performed a lost request.
