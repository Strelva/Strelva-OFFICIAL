## Separate authentication defect

Fresh local Supabase password sessions have signed `amr` method/timestamp entries
and no `auth_time`. CLI and browser step-up previously rejected those fresh
sessions. Commit `010c627b` reads supported sign-in events from cryptographically
verified claims, preserving explicit `auth_time` when present. Browser claims
must match the verified user's subject. Invalid/future timestamps and unknown,
refresh, recovery or account-change methods do not grant freshness. Existing
action maximum ages remain in force; `iat` is never authentication time.

Primary semantics: [Supabase JWT fields](https://supabase.com/docs/guides/auth/jwt-fields).
`pnpm check:authentication-time` creates one disposable loopback Auth user,
performs an actual password sign-in and refresh, verifies a newer issued-at with
unchanged authentication time, and deletes the user. No forged JWT, printed
credential or production configuration is involved. Observed authentication
times: `1791466813` before and after refresh; token issued-at advanced.
