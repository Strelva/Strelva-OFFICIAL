# Approve an improvement by email

[Internal 1.0 draft](../README.md). The owner decides whether the exact proposed
change should go ahead.

## Read and confirm a decision

1. Open the decision email. Read what changes, what approval does and what
   **Not yet** does.
2. Select **Approve** or **Not yet**. Opening the link alone does not decide.
3. On the confirmation page, select **Confirm — approve** or **Confirm — not yet**.
4. Read the result. If the item changed, expired or was already handled, use the
   current decision instead of retrying the old link.

These confirmation controls exist. For pushed Versions, the current adapter
still requires an owner who is a workspace member. The complete no-account
Version approval flow remains [NOT BUILT — tracked in #273]. At 1.0, the named
owner will follow the same email-and-confirm steps without creating an account.

The neutral agency review path remains [NOT BUILT — tracked in #249]. Agency
branding on the email remains [NOT BUILT — tracked in #264]. Email delivery
also needs the release gates and verified sending permission; a prepared update
does not mean an email was sent.

Approval permits the stated action. Check its outcome separately. Do not treat
an approval, Version snapshot or notification as proof that a live site changed.
